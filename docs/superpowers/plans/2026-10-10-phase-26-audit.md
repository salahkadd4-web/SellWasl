# Phase 26 — Audit : plan de réalisation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** le journal d'audit est complet (contexte, catalogue des actions) et consultable par l'admin (API, export CSV, écran Web).

**Architecture:** `AuditService` lit le contexte de la requête (nestjs-cls) ; catalogue typé des actions dans `packages/validation` ; module `audit` avec contrôleur de lecture paginé (helper `paginate` de la phase 25) ; page Web sur le modèle des listes paginées.

**Tech Stack:** NestJS 11, nestjs-cls, Prisma 7, Zod 4, Next.js 16.

**Spec:** `docs/superpowers/specs/2026-10-10-phase-26-audit-design.md`

## Global Constraints

- Consultation réservée à `audit.read` (admin) ; isolation par entreprise.
- Journal en ajout seul (déclencheur existant) ; aucun secret dans `before` / `after`.
- Export CSV : « ; », BOM, cellules neutralisées, 10 000 lignes au plus.
- Fusion locale dans `main`, sans push ; CI locale verte.

## Review Focus

1. Une action faite depuis le téléphone (synchronisation) porte l'appareil du téléphone (tâche 1).
2. Tâches de nuit sans requête : l'écriture du journal ne casse pas (tâche 1).
3. Le filtre de période suit le fuseau de l'entreprise (tâche 3).
4. Une valeur avant/après qui commence par « = » est neutralisée dans le CSV (tâche 3).
5. Un utilisateur d'une autre entreprise ne voit aucune ligne, même avec un `entityId` connu (tâche 3).
