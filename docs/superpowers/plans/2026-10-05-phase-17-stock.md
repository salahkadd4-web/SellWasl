# Phase 17 — Entrepôt et stock : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tenir le stock par mouvements (entrées, inventaire, chargement, déchargement, réservations) avec un registre unique, et les écrans Web correspondants.

**Architecture:** Un service `StockLedger` (module `apps/api/src/stock/`) applique tout mouvement : verrou des lignes `Stock`, contrôle par les fonctions pures de `packages/business-rules/src/stock.ts`, écriture des soldes et des `StockMovement`. Les documents (entrées, inventaires, chargements, déchargements) sont des services au-dessus, exposés en REST et utilisés par six pages Web sous `/app/stock`.

**Tech Stack:** NestJS 11, Prisma 7 (PostgreSQL), Zod 4, Vitest ; Next.js + Tailwind (`@/components/ui`).

**Spec:** `docs/superpowers/specs/2026-10-05-phase-17-stock-design.md`

## Global Constraints

- Toute variation de `Stock` passe par `StockLedger.apply` ; aucun `tx.stock.update` ailleurs (BR-STK-03).
- Stock physique jamais négatif ; `reserved ≤ physical` ; une opération s'applique entièrement ou pas du tout (BR-STK-04, BR-STK-05).
- Quantités stockées en unité de base ; saisie `{ variantId, unitId, qty }` convertie par `qty × unit.baseQty`.
- Erreurs : `rule()` (422 `BUSINESS_RULE`), `invalidState()` (409), `notFound()`, Zod → `VALIDATION_ERROR`.
- Textes visibles en français ; motifs et audits comme les phases précédentes.
- Web : checklist UI (scratchpad `phase17-ui-checklist.md`) — `PageTitle`, `StockTabs` copié de `CatalogTabs`, listes en `Card` + `rounded-xl border`, `Modal` pour les formulaires, `Alert` + `errorMessage`, jetons du thème seulement.
- Tests d'intégration : base `_test` partagée, fichiers en série ; nettoyer ce qui gêne les autres fichiers (commandes non livrées annulées en `afterAll`).

## Review Focus

1. Deux opérations simultanées sur le même article (chargement + réservation) : jamais de survente — test de concurrence en tâche 4.
2. Article sans ligne `Stock` (jamais entré) visé par une entrée, un comptage ou un chargement : ligne créée à 0 ou refus clair, jamais une erreur Prisma brute — tests en tâches 5 et 7.
3. Déchargement d'un camion avec P-06 « garder le stock » : le compté reste et devient le départ du lendemain — test en tâche 8.
4. Inventaire validé pendant que des commandes réservent : l'attendu est recalculé à la validation, pas celui du brouillon — test en tâche 6.
5. Unité d'un autre produit envoyée avec un article : refusée — test en tâche 5.

```ts
/** Stock d'un entrepôt pour un article (BR-STK-02) : disponible = physique − réservé. */
export interface StockBalance { physical: number; reserved: number }
export type StockMoveType = 'IN' | 'OUT' | 'TRANSFER' | 'ADJUSTMENT' | 'RESERVATION' | 'RELEASE';

/** Solde après un mouvement, ou null s'il viole BR-STK-04 (physique ≥ 0, 0 ≤ réservé ≤ physique). */
export function applyMove(b: StockBalance, d: StockBalance): StockBalance | null {
  const next = { physical: b.physical + d.physical, reserved: b.reserved + d.reserved };
  if (next.physical < 0 || next.reserved < 0 || next.reserved > next.physical) return null;
  return next;
}

/** Effet d'un mouvement sur chaque entrepôt (BR-STK-03). */
export function moveDeltas(m: { type: StockMoveType; qty: number; fromWarehouseId?: string | null; toWarehouseId?: string | null }) {
  const out = (id: string | null | undefined, physical: number, reserved: number) => {
    if (!id) throw new Error(`Mouvement ${m.type} sans entrepôt`);
    return { warehouseId: id, delta: { physical, reserved } };
  };
  switch (m.type) {
    case 'IN': return [out(m.toWarehouseId, m.qty, 0)];
    case 'OUT': return [out(m.fromWarehouseId, -m.qty, 0)];
    case 'TRANSFER': return [out(m.fromWarehouseId, -m.qty, 0), out(m.toWarehouseId, m.qty, 0)];
    case 'ADJUSTMENT': return m.fromWarehouseId ? [out(m.fromWarehouseId, -m.qty, 0)] : [out(m.toWarehouseId, m.qty, 0)];
    case 'RESERVATION': return [out(m.toWarehouseId, 0, m.qty)];
    case 'RELEASE': return [out(m.fromWarehouseId, 0, -m.qty)];
  }
}

/** Ligne de déchargement (BR-STK-07) : chargé = théorique + livré + offert ; écart = compté − théorique. */
export function unloadLine(x: { theoretical: number; delivered: number; free: number; counted: number }) {
  return { loaded: x.theoretical + x.delivered + x.free, gap: x.counted - x.theoretical };
}

/** Réservations à libérer quand le stock compté passe sous le réservé : commandes les plus récentes d'abord. */
export function releaseNewestFirst<T extends { confirmedAt: Date; reservedQty: number }>(lines: T[], shortfall: number) {
  const result: { line: T; release: number }[] = [];
  let rest = shortfall;
  for (const line of [...lines].sort((a, b) => b.confirmedAt.getTime() - a.confirmedAt.getTime())) {
    if (rest <= 0) break;
    const release = Math.min(rest, line.reservedQty);
    if (release > 0) result.push({ line, release });
    rest -= release;
  }
  return result;
}

export const isLowStock = (available: number, threshold: number | null) => threshold !== null && available < threshold;
```

export class StockLedger {
  async mainDepot(tx: Pick<Tx, 'warehouse'>) { /* code de OrderService.depot, inchangé */ }

  /** Verrouille (et crée à 0) les lignes de stock d'un entrepôt, dans l'ordre des articles. */
  async balances(tx: Tx, warehouseId: string, variantIds: string[]) { return this.lock(tx, [...new Set(variantIds)].map((v) => [warehouseId, v])); }

  async apply(tx: Tx, actor: Actor, moves: Move[], occurredAt = new Date()) {
    if (moves.length === 0) return;

    const balances = await this.lock(tx, keys, actor.companyId);

        const k = `${warehouseId}:${m.variantId}`;
        const next = applyMove(balances.get(k)!, delta);
        if (!next) throw await this.insufficient(tx, warehouseId, m.variantId, balances.get(k)!);
        balances.set(k, next);
