# Phase 25 — API et intégrations : plan de réalisation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** l'API tient tout son contrat (api.md §1-2) : OpenAPI, idempotence, conflit de version, pagination et tri, erreurs homogènes.

**Architecture:** briques transverses de l'API (générateur OpenAPI depuis les métadonnées Nest et les schémas Zod, intercepteur d'idempotence, helper de pagination, contrôle de version), branchées route par route ; Web et mobile suivent.

**Tech Stack:** NestJS 11 (`DiscoveryService`), Zod 4 (`z.toJSONSchema`), Prisma 7, `swagger-ui-dist`, Next.js 16, Expo 57.

**Spec:** `docs/superpowers/specs/2026-10-07-phase-25-api-design.md`

## Global Constraints

- OpenAPI servi à `/api/docs` seulement si `NODE_ENV !== 'production'` ou `API_DOCS=on`.
- `Idempotency-Key` : 8 à 100 caractères, gardée 24 h, unique par entreprise ; `422 IDEMPOTENCY_MISMATCH`, `409 IN_PROGRESS`.
- Version : facultative dans la requête ; différente → `409 VERSION_CONFLICT` avec `details.current`.
- Pagination : `limit` 50 par défaut, 200 au plus ; `{ data, nextCursor, total }` ; `sort` limité à une liste par route.
- Erreurs : `{ error: { code, message, details?, requestId } }`.
- Fusion locale dans `main`, sans push ; CI locale verte.

## Review Focus

1. Deux requêtes simultanées avec la même clé d'idempotence : une seule exécution (tâche 3).
2. Une erreur métier avec une clé : la clé n'est pas « brûlée », on peut réessayer (tâche 3).
3. Deux modifications concurrentes avec la même version : la seconde reçoit 409 même si elles arrivent ensemble (tâche 4).
4. Curseur d'une liste triée par un champ non unique (même date) : aucune ligne perdue ni répétée entre pages (tâche 5).
5. La documentation ne fuit pas en production (tâche 2).
