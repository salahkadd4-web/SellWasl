# Phase 29 — CI/CD : plan de réalisation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** chaque modification passe par lint, types, tests, compilation et parcours de bout en bout, et produit des images Docker prêtes à déployer.

**Architecture:** configuration ESLint partagée en paquet ; workflow GitHub Actions en jobs parallèles ; Dockerfiles par application à partir de `turbo prune` ; composition Docker d'essai ; workflow mobile sur demande.

**Tech Stack:** ESLint 9 (flat config), typescript-eslint, GitHub Actions, Docker (node 22), GHCR, EAS.

**Spec:** `docs/superpowers/specs/2026-10-12-phase-29-ci-cd-design.md`

## Global Constraints

- Les commandes locales (`pnpm lint`, `pnpm build`, `pnpm test`, `pnpm test:e2e`, `next start`) restent inchangées pour le développeur.
- Aucun secret dans le dépôt ni dans les images.
- Fusion locale dans `main`, sans push ; CI locale verte.

## Review Focus

1. `PLATFORM_ALLOWED_IPS` et `TRUST_PROXY` lus au démarrage de l'image Web, pas figés à la compilation.
2. L'image API démarre sans les dépendances de développement (Prisma CLI, dotenv, client généré présents).
3. Une pull request ne publie jamais d'image ; seules `develop` et `main` publient.
4. Les parcours e2e de la CI utilisent la base du service PostgreSQL (port 5432), pas 5433.
5. Le lint ne fait pas de travail inutile (dossiers générés, compilés et `coverage` ignorés).
